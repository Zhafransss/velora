### Isi konektor (`connector/`)

- Satu socket dan satu folder kredensial per channel (creds dan Signal keys).
- API internal hanya di `127.0.0.1` dengan Bearer token: start, status, QR, kirim pesan, stop/revoke, metrics.
- Pesan masuk diteruskan lewat webhook bertanda tangan HMAC-SHA256; deduplikasi per ID pesan.
- Reconnect dengan exponential backoff dan batas percobaan; QR kedaluwarsa berhenti sendiri; logout menghapus kredensial.
- Pesan keluar diserialkan per channel, ada jeda acak dan indikator mengetik (mitigasi blokir).
- File systemd (`deploy/velora-connector.service`) dengan batas memori 1,5 GB.
- Skrip `scripts/pair.js` (QR di terminal) dan `scripts/smoke.js` (uji N session paralel).
- Panduan uji WA-MT-01..07 di `connector/README.md`.

## 4. Rencana besok

### A. Tindakan pemilik produk di VPS (pemblokir utama Tahap 0)

1. `git fetch && git checkout feature/poc-baileys` di VPS, lalu `cd connector && npm ci`.
2. Salin `.env.example` menjadi `.env`. Isi `CONNECTOR_TOKEN` (min 32 karakter) dan `AUTH_DIR` (di luar web root, misalnya `/var/lib/velora/auth`).
3. Jalankan: `node --env-file=.env src/index.js`.
4. Pairing 3 nomor testing: `CONNECTOR_TOKEN=... node scripts/pair.js poc_a` (lalu `poc_b`, `poc_c`).
5. Jalankan tabel uji di `connector/README.md` (WA-MT-01, 02, 03, 04, 06, 07) dan catat hasilnya.
6. Ambil `curl -H "Authorization: Bearer $CONNECTOR_TOKEN" http://127.0.0.1:3100/metrics` setelah ketiga nomor terhubung (idle) dan setelah beberapa pesan, untuk NFR-007 (kapasitas).
7. Kirim hasil dan log (tanpa token) ke sesi Claude.

## 5. Risiko dan hal yang perlu diingat

- Baileys yang dipakai adalah `7.0.0-rc14` (release candidate). Pesan masuk bisa memakai alamat `@lid`; perilaku balasan ke alamat ini harus dicek di nomor testing.
- Memori session yang baru di tahap QR lebih kecil dari session terhubung. Angka kapasitas yang jujur hanya didapat setelah pairing.
- Hanya 1 snapshot VPS: bukan backup. Backup MySQL dan folder auth ke luar server wajib sebelum pilot (NFR-005).
- Jangan jalankan `migrate:fresh` atau migrasi destruktif pada database yang melayani website produksi.
- Push dari sesi Claude sempat ditolak pemeriksa izin; push dilakukan manual dengan `! git push`.
